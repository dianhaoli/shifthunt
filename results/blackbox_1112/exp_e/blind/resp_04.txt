# Using a Sparse Autoencoder to Remove Spurious Feature Reliance

The canonical version of this method is **SHIFT** (Sparse Human-Interpretable Feature Trimming) from Marks et al., *Sparse Feature Circuits* (2024). The main advantage is that it works even when you **have no data in which the spurious and true features come apart**. Human judgment about which features are task-irrelevant stands in for disambiguating data.

## The setup

You have a classifier, for example a language model with a linear probe on top. It was trained on data where a spurious attribute correlates with the label. The standard example is Bias in Bios: classifying professor vs. nurse from biographies where professors are mostly male and nurses mostly female. The classifier may have learned "gender" instead of "profession." You want it to use only the intended signal.

## Step 1: Get SAEs for the model's internal activations

- Train (or obtain pretrained) SAEs on activations at the relevant sites: residual stream, MLP outputs, and attention outputs across layers.
- Train them on **broad, general data**, not just the biased task data, so the features are generic rather than tailored to the shortcut.
- Each SAE decomposes an activation as
  **x = Σᵢ fᵢ(x)·dᵢ + b + ε(x)**,
  where fᵢ are sparse feature activations, dᵢ are decoder directions, and ε is the reconstruction error.
- Check reconstruction quality (MSE, and downstream loss when splicing the SAE in) and sparsity (L0). Keep the error term ε in the forward pass so the model's behavior is preserved exactly.

## Step 2: Find which features drive the classifier's decisions

- Define a metric m, such as the classifier's logit or log-prob for its predicted class.
- Estimate each feature's **indirect effect** on m using attribution patching (a linear approximation):
  **IE(fᵢ) ≈ ∇_{fᵢ} m · (fᵢ_baseline − fᵢ_actual)**,
  with a zero or mean baseline. Integrated gradients is more accurate, especially for early layers.
- Average over the task dataset. Keep features above a threshold, or the top-k per layer. Error terms can be scored too.
- Optionally compute feature-to-feature edges to get a full **sparse feature circuit**. For debiasing, the node list is often sufficient.

## Step 3: Interpret the important features and label them

For each high-effect feature, inspect:
- max-activating dataset examples (and examples across the activation range),
- which output tokens or logits its decoder direction promotes,
- automated interpretability descriptions, if available.

A human then sorts each feature as **task-relevant** (e.g., "medical terminology," "academic publications") or **spurious** (e.g., "female pronouns," "she/her," "female first names," "male-associated words"). This judgment is where outside knowledge enters. You don't need labels for the spurious attribute or a balanced dataset.

## Step 4: Ablate the spurious features

During the forward pass, at each layer containing selected features:
1. Encode the activation with the SAE.
2. Set the spurious features to zero (or their mean).
3. Reconstruct, keeping the error term. Equivalently:
   **x′ = x − Σ_{i ∈ spurious} fᵢ(x)·dᵢ**

Apply this at every layer where spurious features were found. Downstream layers then only see edited activations.

## Step 5 (optional): Retrain the classifier head

- Retrain the probe or head **on the same biased training data**, but with the ablations in place.
- Since the spurious information has been removed upstream, the head must find the intended signal. This often recovers accuracy lost to the ablation.
- Caveat: if spurious information survives in unablated features or the error term, retraining can re-learn the shortcut. Step 6 is designed to catch this.

## Step 6: Evaluate

- **Balanced / worst-group accuracy:** test on held-out data where the spurious and true attributes are decorrelated (e.g., male nurses, female professors). This is the real target metric.
- **Spurious-attribute accuracy:** check how well the classifier's outputs predict the spurious attribute. It should drop toward chance.
- **Original-distribution accuracy:** confirm you haven't destroyed task performance.
- **Controls:**
  - ablate the same number of random or top-attribution-but-relevant features,
  - compare to an "oracle" classifier trained on balanced data,
  - compare to concept-erasure baselines (LEACE, INLP). These need spurious-attribute labels, which SHIFT doesn't.

In the original paper, this procedure moved balanced-set accuracy from roughly what you'd expect of a gender-reliant classifier to close to the oracle, while gender predictability fell to near chance.

## Pitfalls and caveats

- **Imperfect disentanglement:** feature splitting and *feature absorption* can mix in spurious information. For example, a "nurse" feature may partly encode gender. Ablating it hurts the task; leaving it leaks the bias.
- **Error term leakage:** spurious information carried in ε is invisible to the method. Monitor how much effect is attributed to error nodes.
- **Redundancy / self-repair:** the model may encode the attribute in many places. Ablating a few features can be compensated downstream, so ablate across layers and verify empirically.
- **Attribution approximation errors:** linear attribution can misrank features, especially where activations are saturated or the model is highly nonlinear.
- **Interpretation errors:** humans may mislabel polysemantic features. Look at many examples and the full activation distribution, not just the top activations.
- **Baseline choice:** zero vs. mean ablation can push activations off-distribution differently.
- **Scope:** this works best when the spurious concept is cleanly represented by a modest number of features. Diffuse or subtle shortcuts are much harder.

## Summary

Decompose activations with SAEs, attribute the classifier's output to SAE features, have a human flag the features that encode the spurious concept, zero them out during inference (optionally retraining the head afterward), and confirm on decorrelated data that the classifier now relies on the intended signal.
