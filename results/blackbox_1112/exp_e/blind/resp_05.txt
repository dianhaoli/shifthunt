# Using a sparse autoencoder to remove reliance on a spurious feature

**Setup:** A classifier `f(x) = head(backbone(x))` has learned a shortcut. A spurious attribute `s` (background, watermark, demographic proxy, etc.) is correlated with label `y` in training. The goal is to make predictions depend on `s` as little as possible without hurting accuracy on the real signal.

## Step 1: Choose a layer and collect activations
- Pick a layer where the shortcut is likely represented. The penultimate layer is the simplest, but a mid-layer residual stream also works.
- Run a broad dataset through the backbone and save activations `h`. Include data where `s` and `y` are decorrelated if you can, since this helps the SAE represent `s` separately from `y`.

## Step 2: Train the sparse autoencoder
- Architecture: `z = ReLU(W_enc (h − b_dec) + b_enc)`, `ĥ = W_dec z + b_dec`.
- Loss: reconstruction MSE plus an L1 penalty on `z`. A TopK or BatchTopK activation can replace the L1 penalty.
- Use an overcomplete dictionary (roughly 8–64× the activation dimension), and watch for dead features (resample or use auxiliary losses).
- **Sanity check:** splice the SAE into the model, replacing `h` with `ĥ`, and confirm that classifier accuracy stays close to the original. If it doesn't, the SAE is too lossy to trust.

## Step 3: Find candidate spurious features
You need some signal about `s`, such as a small set of examples labeled for `s`, counterfactual pairs, or group labels (y, s). For each SAE feature `i`, compute:
- **Association with `s`:** AUROC, correlation, or mutual information between `z_i` and `s`, ideally within each class so you don't confuse `s` with `y`.
- **Contribution to the decision:** attribution such as `z_i · ∂logit/∂z_i`, or the direct effect `z_i · (w_head · d_i)` for a linear head.
- **Qualitative inspection:** look at top-activating examples (or use auto-interpretation) to confirm that the feature is about the shortcut.

Flag features with high association to `s` and high attribution to the prediction. If you have no `s` labels, look at features that dominate attributions on minority-group errors or that separate majority from minority examples, and then label them by inspection.

## Step 4: Validate causally
Association isn't enough. For the flagged set `S`:
- Ablate the features (set `z_S = 0`) and check that predictions on shortcut-consistent examples shift as expected.
- Use counterfactual tests, such as swapping the background, and check that the model's output tracks `s` before the edit and no longer does after it.
- Check that ablation does not reduce accuracy on examples where `s` is uninformative. If it does, the features are entangled with real signal.

## Step 5: Intervene
Pick one or combine several:

1. **Inference-time ablation (no retraining):**
   `h_edit = h − Σ_{i∈S} z_i d_i`
   This subtracts only the flagged components and leaves the SAE reconstruction error in place, so you don't pay the full reconstruction loss.
2. **Direction projection:** project `h` onto the orthogonal complement of the span of `{d_i : i ∈ S}`. This is more robust if the shortcut is split across several near-duplicate features.
3. **Head retraining on SAE features:** zero out `S`, then retrain the final layer on `z` with sparsity regularization, ideally on a small group-balanced set. This is similar to last-layer retraining but with interpretable inputs.
4. **Fine-tuning with a penalty:** add an attribution penalty on `S`, or randomly ablate or scramble `z_S` during training so the network can't rely on it. Re-extract and re-check the features afterward.

## Step 6: Evaluate
- **Worst-group accuracy** and the gap between majority and minority groups.
- Accuracy on a **decorrelated or counterfactual test set**, which must not be used for choosing features or thresholds.
- A **linear probe for `s`** on the edited activations. If it is still decodable, the information is leaking through other features.
- Overall in-distribution accuracy, to verify you haven't broken the model.
- Baselines: group DRO, last-layer retraining, or a simple linear concept-erasure method like INLP or LEACE. The SAE approach should be competitive or offer better interpretability and control.

## Step 7: Iterate
- If a residual shortcut remains, look for more features. Feature splitting and absorption mean the shortcut may be spread across several features or hidden inside more general ones.
- Try different dictionary sizes or layers.
- Re-run Steps 3–6 until worst-group performance and the probe results stop improving.

## Caveats
- SAE features may not align cleanly with the concept you care about. Feature splitting, absorption, and polysemantic features are common.
- Ablating features can push activations off-distribution, so test for side effects.
- You need some supervision about `s`, at least a small validation set. Without it, you can't tell what's spurious versus useful.
- Keep the data used to select features separate from the data used for final evaluation, or you'll overstate the improvement.
- If `s` is genuinely informative about `y` in deployment, removing it may reduce accuracy. Decide whether that tradeoff is acceptable.
