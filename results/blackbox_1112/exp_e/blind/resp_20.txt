Here's a step-by-step method. The core idea is to use the SAE to find a human-interpretable direction in the classifier's activations that encodes the spurious cue, then intervene on it.

## 1. Define the spurious feature and build evaluation data

- Identify the spurious attribute (e.g., a watermark, background color, or a demographic proxy) and the label it's correlated with in training.
- You need examples where the spurious attribute and the true label are decoupled, such as a "bias-conflicting" set where the watermark appears on the wrong class. Use it for validation and, ideally, for fine-tuning.
- Annotate the spurious attribute on a held-out set. You need this to score features and to measure success.

## 2. Pick a layer and collect activations

- Choose a layer, typically a residual-stream or MLP-output site in the middle-to-late layers, where the model's representation is rich but still close to the output.
- Run a large, diverse dataset through the classifier and store the activations at that layer. Include both the training distribution and the bias-conflicting examples.

## 3. Train a sparse autoencoder on those activations

- Learn an encoder and decoder, f(x) = ReLU(W_enc·x + b) (or TopK), and x̂ = W_dec·f + b_dec.
- Optimize reconstruction error plus a sparsity penalty (L1 or a TopK constraint).
- Check quality: reconstruction error, fraction of dead features, and ideally how much the classifier's output changes when the activations are replaced by reconstructions.

## 4. Identify features that encode the spurious cue

Score each feature on two criteria:

- **Association:** How well does its activation predict the spurious attribute? Use AUROC or a difference in mean activation between groups.
- **Causal relevance:** Does it influence the classifier's decisions? Measure this by ablating the feature and checking how much the logits change, or by attribution (e.g., gradient × activation) on bias-conflicting examples.
- **Low label overlap:** Prefer features that predict the spurious attribute but not the true label. Removing features tied to the true label would hurt core accuracy.

Rank the features and keep the top candidates. Inspect their top-activating examples to confirm they correspond to the cue.

## 5. Intervene on the spurious features

Several options, from cheapest to most thorough:

**(a) Inference-time ablation.** Keep the classifier frozen and modify the activations in the forward pass:

```python
def hook(x):
    f = sae.encode(x)          # sparse code
    err = x - sae.decode(f)    # reconstruction error, preserved
    f[:, spurious_idxs] = 0    # zero out the spurious features
    return sae.decode(f) + err
```

Keeping the error term means the rest of the representation is untouched except for the removed features.

**(b) Subspace projection.** Take the decoder directions of the spurious features, orthogonalize them, and project them out of the residual stream: x ← x − P·x, where P projects onto their span.

**(c) Training-time removal.** Fine-tune the classifier (or only the head) with the ablation hook active during training. This forces the model to stop relying on the feature, rather than just hiding it at test time. You can also add a penalty on the classifier's sensitivity to the feature's activation, or train on the bias-conflicting set so the model learns a different route.

## 6. Evaluate

- **Worst-group accuracy** on the bias-conflicting set. This is the main metric.
- **Average accuracy** on the standard set, to confirm core performance hasn't collapsed.
- **Spurious-attribute decodability:** train a linear probe on the modified activations to predict the spurious attribute. It should drop substantially. If it stays high, the information is encoded redundantly elsewhere.
- **Feature-level checks:** confirm that ablating the removed features no longer changes predictions on the conflicting set.

## 7. Iterate

- If the probe still decodes the spurious attribute, look for other features that carry it (feature splitting or distributed encoding) and repeat steps 4–6.
- If core accuracy drops, the selected features probably overlapped with label-relevant information. Tighten the label-overlap criterion or pick a different layer.
- Repeat across layers if needed. Removing the cue from several layers is sometimes necessary.

## Caveats

- **Redundancy:** The model may route around the ablation through other features or later layers. Always check with a probe and with downstream accuracy.
- **Entanglement:** SAE features are not guaranteed to be clean. A feature can be polysemantic and mix the spurious cue with useful information.
- **Validation leakage:** If you choose features using the bias-conflicting set and then evaluate on it, your results are optimistic. Keep a separate held-out split.
- **Ground truth matters:** This method only works as well as your annotation of the spurious attribute. Unlabeled spurious cues are much harder to handle.
