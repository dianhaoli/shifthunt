# Removing Spurious Reliance with Sparse Autoencoders

The approach below is essentially **SHIFT** (Sparse Human-interpretable Feature Trimming), introduced by Marks et al. in *Sparse Feature Circuits* (2024). The running example is a profession classifier trained on biographies where gender is spuriously correlated with the label (e.g., nurses mostly female, professors mostly male).

The key selling point: **you can remove the spurious dependence without any data that breaks the correlation.** You only need human judgment about which features are task-relevant.

---

## Step 1: Set up the classifier and the problem

- Take a model (e.g., a language model with a linear probe/head on top) trained on data where the spurious feature is predictive.
- Have, ideally for **evaluation only**, a "balanced" or "ambiguous" test set where the spurious correlation is broken (e.g., equal gender balance within each profession).
- Measure baseline accuracy on the balanced set and on a probe for the spurious attribute (e.g., how well gender can be predicted from the classifier's output). Typically the classifier performs noticeably worse on the balanced set.

## Step 2: Train (or obtain) sparse autoencoders on internal activations

- Train SAEs on activations at the sites you care about: residual stream at each layer, and optionally MLP outputs and attention outputs.
- Each SAE decomposes an activation vector **x** into a sparse set of feature activations **f** plus an error term:
  x ≈ W_dec · f(x) + b_dec, with ε = x − x̂
- Keep the **error term** as part of the computation so the model's behavior is exactly preserved when you splice SAEs in. You don't edit the error term, which means anything the SAE fails to capture won't be removed (an important limitation, see below).

## Step 3: Attribute the classifier's decision to SAE features

Identify which features actually drive the classifier's output, using a metric m such as the logit/probability of the predicted class.

- **Attribution patching (linear approximation):** the indirect effect of feature *i* is estimated as
  IE(f_i) ≈ (∂m/∂f_i) · (f_i^ablated − f_i)
  where the ablated value is zero or the feature's mean.
- **Integrated gradients** is more accurate for early layers where the linear approximation degrades; average gradients along the path from ablated to actual activation.
- Aggregate attributions over a set of training examples (and over token positions, since the classifier may read from a pooled or final token).
- Optionally build a full **feature circuit**: compute edges between features across layers and keep nodes/edges above a threshold, giving a compact graph of the features that matter.

Result: a ranked list of a few hundred features that most influence classification.

## Step 4: Interpret the features

For each high-attribution feature, inspect:
- **Top-activating examples** from a dataset (which tokens and contexts light it up).
- **Logit/output effects:** which tokens its decoder direction promotes or suppresses when projected through the unembedding.
- Optionally, automated explanations from an LLM, then spot-check them.

## Step 5: Judge which features are spurious

A human (or a carefully prompted model) labels each feature as **task-relevant** or **spurious**:
- Task-relevant: "medical terminology," "references to teaching/lecturing," "legal language."
- Spurious: "female pronouns," "male names," "'she'/'her' tokens," "'Mr.'/'Ms.'."

This is the step where human knowledge substitutes for labeled de-biased data. You only need to know *what the classifier shouldn't use*, not examples that demonstrate it.

## Step 6: Ablate the spurious features

Intervene during the forward pass:
- At each relevant SAE site, set the selected features to **zero** (or their **mean** activation), recompute x̂, and add back the error term.
- Apply this at all layers/positions where those features appear in the circuit, since a spurious signal can be represented redundantly across layers.
- Mean ablation is often gentler than zero ablation if features have nonzero baselines.

The modified model is the original plus fixed feature-ablation hooks. No weights are retrained yet.

## Step 7 (optional): Retrain the classifier head

Ablation can leave the classifier somewhat miscalibrated, since it previously relied on the removed signal.
- Retrain **only the classification head** (or a probe) on the original, still-biased training data, with the ablations in place.
- Because the spurious features are gone, the head can't re-learn the shortcut through them, though it might find residual routes (see pitfalls).

## Step 8: Evaluate

Check:
1. **Accuracy on the balanced/ambiguous test set.** This should rise, ideally close to an "oracle" classifier trained on balanced data.
2. **Spurious-attribute accuracy:** how well the spurious attribute (gender) can be predicted from the classifier's output or decision. This should drop toward chance.
3. **Accuracy on the original distribution.** This may drop slightly, since the shortcut genuinely helped there.
4. Compare against baselines: random feature ablation, ablating neurons instead of SAE features, and concept-erasure methods like LEACE or INLP applied to the same activations.

In the Bias in Bios experiments, SHIFT plus head retraining brought performance on the balanced set close to the oracle while pushing gender predictability near chance. Ablating raw neurons, by contrast, worked poorly because gender information was smeared across polysemantic neurons.

---

## Pitfalls and limitations

- **SAE error term:** spurious information not captured by SAE features survives in ε. Check how much of the residual signal remains, for example by probing the error term for the spurious attribute.
- **Redundancy and re-learning:** the information may be encoded in other features you didn't flag. Retraining the head can rediscover it, so re-run attribution after ablation and iterate.
- **Feature splitting / entanglement:** a feature might mix task-relevant and spurious content (e.g., "nursing + female pronouns"). Ablating it hurts the task, and keeping it preserves the bias. Larger SAEs may split it, at the cost of more features to review.
- **Interpretation errors:** humans can mislabel features based on top activations alone. Check activations across the full range, not just the maxima.
- **Attribution approximation error:** linear attribution can miss important features, especially in early layers. Integrated gradients mitigates this.
- **Scale of human review:** reviewing hundreds of features is laborious. Automated interpretation helps but needs verification.

---

## Why this matters

Standard debiasing methods (reweighting, group DRO, counterfactual augmentation) need data where the spurious correlation is broken, or at least labels for the spurious attribute. The SAE approach replaces that requirement with **interpretable access to the model's internal features plus human judgment**. That makes it useful when you can't construct disambiguating data but can recognize a bad reason for a decision when you see it.
