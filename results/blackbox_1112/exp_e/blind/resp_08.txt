Here is a practical pipeline. The core idea is to use the SAE to find an interpretable, sparse direction in the classifier's activations that tracks the spurious feature, verify that the classifier actually uses it, and then remove its influence.

## 1. Define the problem and the spurious attribute

- Identify the classifier's target label *y* and the spurious attribute *s* (e.g., a watermark, background, or demographic proxy that is correlated with *y* in training but not in the true task).
- You need some labels or proxies for *s* on a held-out dataset to measure reliance. If you don't have them, you can often annotate a subset or use a tool to detect the attribute.
- Set aside a **debiasing/validation split** where *s* and *y* are decorrelated (or at least group-balanced), and a **test split** for final evaluation.

## 2. Choose a layer and collect activations

- Pick a layer *L* where the spurious information is likely represented. Later layers are often more task-specific, while the penultimate layer is a common choice for classifiers.
- Run a large, diverse dataset through the model and record the activations **a** = h_L(x) for each input. Store them on disk, since SAE training needs a lot of them.

## 3. Train a sparse autoencoder on those activations

- Architecture: encoder f = ReLU(W_enc(a − b_dec) + b_enc) or a TopK variant, decoder â = W_dec f + b_dec, with a dictionary of size *m* (commonly 4–32× the activation dimension).
- Loss: reconstruction error ‖a − â‖² plus a sparsity penalty (L1 on f, or enforced by TopK).
- Sanity checks before proceeding:
  - Reconstruction fidelity: patching the reconstruction into the model should preserve most of its accuracy ("loss recovered").
  - Dead or dense features: prune or retrain if many features never fire or fire on most inputs.

The SAE gives you a basis of sparse, hopefully interpretable features f_1…f_m, each with a decoder direction d_i in activation space.

## 4. Find candidate features tied to the spurious attribute

Look for features that track *s* beyond what *y* explains. Several complementary scores help:

- **Conditional association:** For each feature, compare its mean activation across groups with the same label but different *s* (e.g., among "cow" images, is the feature higher on beach backgrounds?). Rank by effect size or a t-statistic.
- **Probe-based selection:** Train a linear probe for *s* on the SAE codes. Features with large probe weights are candidates.
- **Attribution:** Multiply each feature's activation by its gradient of the loss or logit difference (attribution patching). Features with large attribution for the shortcut prediction are likely causal.
- **Inspection:** Look at top-activating examples for each candidate. A human check (or automated captioning) confirms the feature really corresponds to the spurious concept.

Typically you end up with a small set S of spurious features. Expect several, since a concept is often split across features.

## 5. Verify causally

Correlation is not enough. Test whether the classifier uses these features:

- **Ablation:** Replace the layer activation with
  â' = â − Σ_{i∈S} f_i d_i,
  keeping the SAE error term (a − â) so that the rest of the representation is unchanged. Zeroing or mean-ablating the features are alternatives.
- **Measure:** Does accuracy on the spurious-disagreeing group (e.g., cows on beaches) improve? Do predictions flip toward the correct label on counterfactual pairs that differ only in *s*?
- **Check selectivity:** Ablating S should hurt core accuracy minimally. If it hurts a lot, the features are entangled with the task, and you'll need to refine S or use a different layer.

## 6. Remove the reliance

Choose one of these, depending on your constraints:

**a) Inference-time ablation (no training).** Apply the ablation from step 5 as a permanent hook. It's cheap and reversible, but it only works if the spurious information doesn't have redundant pathways.

**b) Fine-tuning with the SAE in the loop.**
- Freeze the SAE and insert it at layer *L* so the forward pass goes through the SAE.
- Fine-tune the network with the spurious features clamped to zero (or projected out) during the forward pass. The rest of the model learns to classify without them.
- Optionally add a penalty λ Σ_{i∈S} E[f_i(x)] to the loss to push these features toward inactivity.

**c) Projection/erasure (linear).** Compute the subspace spanned by the decoder directions d_i for i ∈ S and project the activations orthogonal to it (similar to INLP or LEACE). This is more direct than ablating whole SAE features, but it removes less precisely.

## 7. Evaluate thoroughly

- **Worst-group accuracy** and per-group accuracy (*y* × *s* combinations), not just average accuracy.
- **Core accuracy** on the task to confirm you haven't degraded the classifier.
- **Counterfactual tests** on matched pairs that differ only in *s*. Prediction flips should vanish.
- **Probe re-test:** Train a fresh probe for *s* on the edited layer. If it still decodes *s* well, the information persists elsewhere, even if the classifier no longer uses it. That may be acceptable, but it means the removal is weaker than it looks. Removing it from the classifier's decision path is different from erasing it from the representation.
- **Distribution shift:** Evaluate on a new dataset where the spurious correlation is absent or reversed.

## 8. Iterate

- If worst-group accuracy barely moves, the spurious signal likely flows through other features or other layers. Repeat the analysis at a different layer or expand S.
- If core accuracy drops, S includes task-relevant features. Narrow S, or use the fine-tuning option so the model can reroute.
- Increasing SAE width often splits a concept into more specific features, which can make the ablation more precise but also means you need to catch more features.

## Pitfalls to watch for

- **Feature absorption and splitting:** The spurious concept may be spread across features, some of which are polysemantic. Ablating only the top feature leaves residual reliance.
- **Causal bypass:** Ablating at one layer doesn't stop the model from reading the same information from an earlier layer.
- **Label leakage:** Feature selection should use only the validation split. If you pick features on the test set, your results will be optimistic.
- **Over-removal:** Features that look spurious may be partly causal. Always check core accuracy and per-class effects.

In short: train an SAE on the layer, find features that track the spurious attribute beyond the label, confirm causally by ablating them, then either ablate permanently or fine-tune with those features suppressed, and validate using worst-group accuracy and a re-probe.
