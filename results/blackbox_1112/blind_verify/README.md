# blind_verify: what a scripted blind solver can name with B exact queries (plan 0b.3)

Generated by `scripts/blind_verify.py` (commands: `COMMANDS.md`; all numbers: `blind_verify.json`). No cue is named and nothing here says which probe is an episode's hard slot.

**PRIVILEGED scripted ceilings, not agent results.** The solver has no SAE information, but it is handed the episode's list of 8 label-aligned properties, their signs, and the generator's exact edit of each. It does not know which probe is hard or null. These are the best of the scripted policies written here, not a proven optimum.

Episodes: ep411, ep413, ep415, ep472, ep474, ep476 (trap: 3, two-part: 3). 2000 seeded runs per episode, policy and budget (Monte Carlo standard error of one episode's rate at most 0.011; of a pooled rate over 6 episodes at most 0.005). B is the number of exact queries per episode, shared by the 4 probes.

## Cost model and decision rule

- **One query per edited text; the unedited base note is free.** In the blackbox tool set the logits of sample notes come from `probe_scores`, which does not spend `probe_query`; the stored scan bases stand in for sample notes here. A blind agent that edits notes it wrote itself would also pay for the base, roughly halving its readings per budget.
- A reading is the sign-aware true logit difference between a base note and its edited copy. It counts as positive above **0.225 x the probe's topic unit** (midpoint of the prompt's 0.3 and 0.15). Primary unit: the privileged mean topic-swap effect over all 32 stored bases, taken as free. Sensitivity, unit-free: positive above 1.84 logits (10 x 0.225 / 1.225, from the sample gap of exactly 10).
- NAME = the hard slot's claim set equals its main cue(s) and every null probe is answered `none`. ALL = every probe's claim set is right. Rates are per episode; pooled and by-kind rates are means over episodes.
- Back-end A (additive, primary, stored data only): a group text's reading is the sum of the stored single-flip readings of its members on the same scan base. Back-end B (exact): the group texts are re-rendered and their true logits computed on the GPU. Single flips are stored, so policy (i) is exact under both.

## Policies

- **(i) random single flips.** B of the 32 (probe, aligned property) cells, drawn without replacement, one single-flip text each on a random valid base (a child property only on bases with its parent on). A cell that reads positive is claimed (at most 2 per probe). Above 32, cells are read again on new bases and averaged.
- **(ii) bisection, screen first (the plan's policy).** One text per probe with all 8 aligned properties moved to the other label's levels. For the probes that read positive, in random order, the 8 candidates (random order) are halved with one group text per step: 3 texts isolate one. `none` / `guess`: a probe whose search ran out of budget is answered `none`, or with a uniform draw from the candidates still standing.
- **(ii-b) bisection, depth first (added).** The same texts, but each probe is screened and searched to the end before the next one is touched.
- **(ii-c) bisection, no screen, confirm (added).** No all-8 text: halve as if a main exists (3 texts), then read the isolated candidate's single flip and claim it only if that is positive.
- **One main per probe.** A halving search isolates one candidate, so every bisection variant answers a probe with at most one property; on a probe with two main cues it could never be right (only policy (i) can claim two). The script refuses an episode that has such a probe. None of these episodes has one, so no rate here is affected.
- Group texts start from a sample-like base: a stored scan base with every aligned property at the level it has in sample notes of that base's label, so a group text moves its members toward the other label, as an agent editing a sample note would. Every bisection reading uses R bases, R = max(1, B // 16); leftover budget starts the next probe, and what remains at the end is unspent.
- Bases: a single flip of a child property (a variant of its parent's line) is read only on bases with the parent on; group texts only on bases where that holds for every aligned child (trap episodes: 32 of 32 bases per probe; two-part episodes: 13-20 of 32 bases per probe).

## Answer: is a low BB-8 an agent shortfall, or low by budget design?

At B = 8 the best scripted blind policy gets NAME (hard slot named, null probe left alone) in 0.44 ((ii-b) bisection, depth first; incomplete -> guess; trap 0.42, two-part 0.46) of runs with the additive back-end; the plan's two policies alone (random single flips, screen-first bisection) reach at most 0.36. At B = 64 the best is 0.97 ((i) random single flips; trap 0.94, two-part 0.99). With exact group-flip logits from the GPU the best rates are 0.43 ((ii-b) bisection, depth first; incomplete -> guess; trap 0.40, two-part 0.46) at B = 8 and 0.97 ((i) random single flips; trap 0.94, two-part 0.99) at B = 64. With every reading exactly right the same policies reach at most 0.58 at B = 8 and 1.00 at B = 64: there are 32 (probe, aligned property) cells and the hard slot is not marked, so 8 single flips cover a quarter of the cells, and a bisection needs 4 texts per probe, so 8 texts finish two of the four probes. So a low BB-8 NAME rate is mostly **low by budget design**, not an agent shortfall: a solver that is handed the candidate list, the signs and the exact edits, and gets base notes and the topic unit free, tops out near 0.44 at 8 queries and reaches 0.97 at 64. A BB-8 agent rate up to about 0.44 is what the budget allows. The budget does not put BB-8 at the floor, though: a rate near zero would be below this ceiling, and a BB-64 rate well below 0.97 would be an agent shortfall. A BB-8 rate clearly above 0.44 would mean the agent used something this solver lacks, such as a prior about which properties are plausible cues (the two-part hint is not such a thing: it says how to measure a nested property, which this solver already does). Caveats: these are the best of the policies written here, not a proven optimum; a reading uses one base note at B <= 16 (and at B = 32 for single flips), two to four above, so part of every loss is single-base noise; without the privileged topic unit (unit-free rule) the best rates are 0.46 at B = 8 and 0.97 at B = 64; and an agent that had to pay for its base notes would get about half as many readings per budget.
